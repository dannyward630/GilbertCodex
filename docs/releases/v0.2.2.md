# Gilbert Codex v0.2.2

Gilbert Codex v0.2.2 is Stability Pack 1: a milestone patch focused on making the public alpha feel steadier after the signed-updater rollout. It keeps the release train moving while landing terminal, storage, Git review, web-search, chat runtime, and update-flow hardening.

## Download

- Windows x64 installer: `Gilbert-Codex-0.2.2-x64-setup.exe`
- SHA-256: published as `Gilbert-Codex-0.2.2-x64-setup.exe.sha256` on the GitHub release.
- Signed updater signature: `Gilbert-Codex-0.2.2-x64-setup.exe.sig`
- Tauri updater feed: `latest.json`
- Approximate size: published on the GitHub release asset list after the signed build.

This build is still not code-signed with a Windows Authenticode certificate. Windows SmartScreen may ask for extra confirmation before installing.

macOS and Linux release artifacts are not official yet. The repo has partial source support for both platforms, and contributors with those operating systems are needed to test and complete the port.

## Stability Pack 1

- Reworked the embedded terminal around a real PTY-backed interactive session with xterm rendering, resize handling, shell input, clear/restart controls, and cleaner control-sequence handling.
- Added native terminal resize plumbing so the Rust host and frontend terminal stay in sync as the dock changes size.
- Hardened account-scoped Gilbert Database access so desktop storage stays limited to the signed-in local user namespace.
- Moved GitHub account storage and agent-run storage behind the active local-user namespace and clears old shared stores when needed.
- Expanded local Git status with head SHA, upstream, ahead/behind counts, and diff previews.
- Added local Git commit, branch creation, and push actions to the native command layer.
- Upgraded the Git review panel with richer branch context, selected-file diff previews, review passes, and commit/branch/push controls.
- Tightened DuckDuckGo web search with connect/client/source timeouts and a total search budget so stalled searches fail cleanly.
- Improved provider streaming by honoring response snapshots when streaming deltas arrive out of order or arrive as partial response state.
- Added generated chat titles with short, tool-free provider calls and safe fallbacks.
- Added targeted stop behavior for individual streaming responses and clearer cancelled agent-run state.
- Stopped the Discord bridge on logout so local account switches do not leave old runtime state hanging around.
- Started update checks earlier in the desktop session now that signed release feeds are publishing.

## Roadmap Research Notes

- Meta's WhatsApp Cloud API is the official business messaging path for programmatic WhatsApp communication, so any WhatsApp support should be designed around explicit business/user-approved workflows: https://developers.facebook.com/docs/whatsapp/cloud-api
- OpenAI's image-generation docs support conversational generation and editing flows that fit a future Gilbert media tool surface: https://platform.openai.com/docs/guides/images/image-generation
- OpenAI's video-generation docs describe queued render jobs, status polling, downloads, thumbnails, and spritesheets, which maps well to Gilbert's activity rail and artifact model: https://platform.openai.com/docs/guides/video-generation

## Known Limits

- Windows x64 is still the only official packaged target for this release.
- The installer is not code-signed with a Windows Authenticode certificate yet.
- macOS and Linux still need native contributors to validate launch, packaging, shell behavior, and platform-specific fixes.
- WhatsApp, image generation, video generation, and the model-selector revamp are roadmap items, not shipped features in v0.2.2.
- Provider keys, GitHub tokens, Discord settings, local accounts, logs, workspace data, local databases, release signing credentials, and updater private keys remain local user data and are not bundled.
