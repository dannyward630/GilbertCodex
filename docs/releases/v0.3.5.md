# Gilbert Codex v0.3.5

Gilbert Codex v0.3.5 is a public alpha update focused on a cleaner local desktop runtime, refreshed contributor-facing documentation, and a safer public repository posture.

This is still alpha software. Provider and model behavior varies, and some edge cases are still being tightened as real users test the app. High-impact local actions, publishing, credential access, destructive operations, and outside-scope paths should remain behind visible review.

- Version: `0.3.5`

- Previous public milestone: `v0.3.0`
- Primary packaged target: Windows x64
- Release vehicle: GitHub Actions `Release` workflow plus Tauri NSIS installer

Do not fill the checksum until the final installer artifact has been built and uploaded. Keep the GitHub Release body aligned with this file.

## Who This Build Is For

This build is for people who want to test Gilbert Codex as a local-first desktop coding agent workspace:

- Developers who want chat, local projects, provider routing, GitHub setup, Discord setup, source cards, and SQL-backed local state in one app.
- Alpha testers who can report provider/model reliability with concrete prompts and model IDs.
- Contributors who want a clearer source tree and release checklist.
- Maintainers preparing release notes, installer artifacts, and public issue triage for a wider audience.

## Runtime Boundary

v0.3.5 keeps the app's local runtime and provider request paths explicit:

- Provider request creation is easier to inspect and validate.
- Permission-sensitive local actions remain review-gated.
- Visible activity and source cards should stay user-readable instead of exposing internal protocol text.
- Local data, generated outputs, diagnostics, and private automation sources stay out of Git.
- Source context is bounded so follow-up turns do not flood provider requests.

## Source Context

Source-backed answers remain a focus:

- DuckDuckGo/Brave source context uses a six-source cap.
- Source cards are attached to chat for citation review.
- Planning and thinking mode can receive source context without losing citation requirements.
- Browser fallback behavior stays separate from desktop Rust search routing.

## Upgrade Notes For Users

- Install the Windows x64 setup executable from GitHub Releases.
- If Windows SmartScreen appears, review the source before continuing. This alpha is unsigned unless a signed build is provided.
- Configure provider keys, local endpoints, GitHub OAuth, Discord, and workspace permissions from Settings.
- For local models, start LM Studio or Ollama first, confirm the endpoint is reachable, then select the matching provider/model in Gilbert.
- Keep local databases, logs, screenshots, provider errors, and workspace paths out of public issues unless they are sanitized.

## Upgrade Notes For Maintainers

- Keep version fields aligned across `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`, and `src-tauri/tauri.conf.json`.
- Keep `docs/releases/v0.3.5.md` aligned with the GitHub Release body.
- Use `npm.cmd` on Windows PowerShell if the `npm` shim is blocked by script policy.
- Run the full build and Rust check before pushing a release tag.
- Confirm the release workflow has `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` when updater artifacts are required.
- Confirm generated artifacts, logs, local database files, secrets, dependency folders, and private local runtime sources stay out of Git.

## Known Issues

### Provider And Model Reliability

Some hosted and local models behave differently across structured output, long context, empty responses, and source-backed synthesis.

Workarounds:

- Try a model known to behave well for the current task.
- Try a local model through LM Studio or Ollama when cloud routing is unstable.
- Retry with a more direct instruction if the model drifted.
- Include provider, model ID, prompt, and sanitized visible activity details when reporting.

### Approval UX Still Needs Polish

Risk-based review exists, but approval cards, grouped activity, and final review surfaces still need more real-world refinement.

### Windows-Only Packaged Release

Windows x64 is the only official packaged target for v0.3.5. macOS and Linux source support exists, but official release artifacts require native validation.

### Unsigned Windows Installer

The installer is not Authenticode code-signed unless a release is built with valid signing configuration. SmartScreen warnings are expected on some machines.

## Security And Privacy Notes

Gilbert Codex is local-first. Provider keys, GitHub tokens, Discord settings, local accounts, local databases, logs, workspace files, scan artifacts, release signing credentials, updater private keys, and private local runtime sources are local user data. They should not be committed or attached to public issues.

The release continues the repository hygiene posture:

- `.env` stays ignored.
- Local SQLite databases stay ignored.
- SQLite journal and WAL files stay ignored.
- Local scan outputs stay ignored.
- Dependency folders stay ignored.
- Build outputs stay ignored.
- Release signing credentials stay out of source control.

## Production Readiness Posture

v0.3.5 is prepared for broader public alpha testing. It has a cleaner runtime boundary, more honest docs, stronger release prep, and a privacy posture that keeps sensitive local sources out of Git.

It is not claiming perfect provider reliability. The right release posture is to ship the build with explicit known issues, gather compatibility reports, and continue tightening the runtime with real evidence.
