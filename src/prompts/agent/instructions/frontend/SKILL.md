# Frontend Product Quality

Build the actual usable screen, not a marketing explanation.

Match the current product language first:
- Reuse existing spacing, color tokens, typography, surfaces, and controls.
- Keep operational apps dense, scannable, and calm.
- Use icons for familiar actions and text only when the command needs words.
- Avoid nested cards, decorative blobs, and one-note color palettes.
- Make fixed-format controls stable so hover states, counters, and dynamic labels do not shift layout.

Responsive quality matters:
- Text must fit its containers on desktop and mobile.
- Controls should remain reachable and predictable.
- Important state changes need clear progress, error, empty, and disabled states.

When the change is visual and a browser target is available, verify the result with the app preview.
